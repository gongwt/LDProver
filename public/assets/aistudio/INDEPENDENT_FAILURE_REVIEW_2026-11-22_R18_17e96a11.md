**R17 的 P1 可以关闭。R17 点名的缺历史表导出问题也已解决。** 公开导出仍有一项 P2：对声称已经定论的报告，没有检查它是否包含一个可引用的证明根节点。正常求解产生的 8 份定论文件全部通过原题绑定复核。

## 1. P2　缺少证明根的定论报告仍能导出

使用正式 p001 的同一次求解，保留棋面、目标、配置、非空状态表和历史表。每次只改变一项内存报告字段，调用公开的 `serializeLProofJson`，再将返回的 JSON 原样提交给 `verifySerializedLProofJson`，绑定正式原题及 original_root 作用域。

| 输入 | 公开导出结果 | 独立文件回读 |
|---|---|---|
| 完整 p001 | 2 个 DAG 节点，根编号 1，返回 JSON 和摘要 | PASS |
| 缺少 historyTable（R17 原例） | 导出前抛出带 LP-J02 的错误 | 没有生成文件 |
| proofDagNodes 为空数组，根编号仍为 1 | 导出成功，文件声明 PROVEN_WIN、0 个节点、根编号 1 | LP-R00 |
| 保留 2 个 DAG 节点，缺少 rootDagNodeId | 导出成功，文件声明 PROVEN_WIN，缺少 rootNode | LP-J02 |

`src/engine/proofChecker.ts:581` 从遍历数组元素开始检查 DAG，空数组不会触发节点检查。公开方法在第 1196 行起检查完整表结构、区域声明和已定论报告的状态表长度；第 1322 行将根编号直接写入文件。这解释了为何“状态表有两行”足以越过导出预检，而文件内部仍无从定位证明根。影响限于导出阶段：复核器对两份文件均给出失败，未观察到胜负误判。

**建议验收条件。** 对 PROVEN_WIN 和 PROVEN_LOSS，导出前确认 DAG 非空，rootDagNodeId 是表内整数且所指节点的 nodeId 与之相符。把空 DAG、缺失和越界根编号与正常胜证、败证放在同一组导出回读测试中。这个检查只需要查看数组长度和一个节点，UNKNOWN 部分搜索仍可保留无定论根的诊断记录。
